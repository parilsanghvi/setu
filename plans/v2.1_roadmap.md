# Setu v2.1 Roadmap: "The Enlightened Swarm"

**Architect:** Bhondu & Paril
**Date:** Feb 18, 2026
**Status:** Draft / Architectural Spec

## 🎯 Executive Summary
Setu v2.0 established the "Unhinged Agency" with a robust event-driven kernel. v2.1 aims to optimize the "Brain" (Tokenomics, Context), stabilize the "Body" (Resurrection logic, Git ops), and beautify the "Face" (Mission Control UI).

---

## 1. 🧠 Core Intelligence & Tokenomics

### A. State-Based Memory (The "Anti-Chatter" Protocol)
**Problem:** Currently, agents rely on a sliding window of chat logs. This is reactive, expensive, and dilutes instructions with conversational noise ("I'm online", "Ok", "Done").
**Solution:** Move from *Conversation History* to *State Injection*.

**Implementation Strategy:**
Instead of feeding the LLM `[User: Do X, Agent: Ok, Agent: Doing X]`, we maintain a `state.json` for each agent and inject it into the System Prompt dynamically.

```typescript
// CoreAgent.js State Schema
interface AgentState {
  identity: {
    name: "Tark";
    role: "Backend Lead";
  };
  mission: {
    id: "TASK-101";
    objective: "Optimize API";
    constraints: ["No console.log", "Use JSON logger"];
  };
  context: {
    filesRead: ["package.json", "server.js"]; // Cache keys
    lastError: null | string;
    stepsCompleted: ["Read file", "Parsed AST"];
  };
}
```

**Action:**
1.  Refactor `CoreAgent` to maintain `this.state`.
2.  Update `prepareLlmMessages()` to prioritize `SYSTEM_PROMPT + JSON.stringify(this.state)` over raw chat history.
3.  Implement a "Signal Filter" in `Sutradhar`: Drop generic acknowledgments; only forward messages that change state or contain new data.

### B. Shared Knowledge Cache (The "Hive Mind")
**Problem:** Multiple agents (e.g., Tark & Shilpi) independently read the same config files (`package.json`, `.env`), wasting tokens and I/O.
**Solution:** A Redis-like in-memory store (or SQLite table `cache`) for file contents.

**Mechanism:**
*   **Write:** When Agent A reads `server.js`, store `{ path: "server.js", hash: "sha256...", content: "..." }` in DB.
*   **Read:** When Agent B asks to read `server.js`, check DB. If file mtime hasn't changed, return cached content immediately (skipping FS access).
*   **Token Save:** If content is large, don't feed the whole file to LLM unless necessary. Feed the *summary* or *structure* first (using AST parsing).

## 2. 🗣️ The Language Strategy

**Decision:** **Reject Multi-lingual (Sanskrit/Chinese) Prompts.**
**Reasoning:**
*   **Bias:** Coding LLMs are optimized for English tech docs. Non-English reasoning increases hallucination risk.
*   **Density:** While Chinese is token-dense, it loses semantic precision for code concepts.

**New Standard: "Pseudo-Code Prompts"**
Replace natural language paragraphs with TypeScript Interfaces in System Prompts.

**Example (Old):**
> "You are a backend engineer. You must validate inputs. Do not allow SQL injection."

**Example (New - v2.1):**
```typescript
interface BackendEngineer {
  role: "Sentinel";
  securityPolicy: {
    inputValidation: "Zod Schema Required";
    sqlInjection: "Use Parameterized Queries Only";
  };
  onError: "Throw 400 Bad Request";
}
```
*   **Impact:** Cheaper (less tokens), higher adherence (model treats it as code constraints).

## 3. 🖥️ UX: Mission Control Dashboard

**Goal:** Move from "Log Viewer" to "Swarm Command Center".

### A. The Swarm Graph (Visualizer)
*   **Tech:** React Flow or D3.js.
*   **Visual:** A live Force-Directed Graph.
    *   **Nodes:** Agents (Green=Idle, Red=Busy, Gray=Offline).
    *   **Edges:** Active communication channels.
    *   **Animation:** Packets traveling along edges when messages are sent.

### B. "Thought Bubble" Mode
*   **UI:** Collapsible `<Thinking>` accordion in the chat stream.
*   **Data:** Expose the internal `reasoning` or `chain_of_thought` from the LLM response (if model supports it) or the agent's pre-computation steps.
*   **Why:** Builds trust. User sees *why* Tark rejected the PR.

### C. The "God Mode" Editor (Intervention)
*   Allow the user to edit the Agent's `state.json` directly from the UI.
*   **Scenario:** Agent is stuck in a loop trying to read a missing file.
*   **Fix:** User edits state: `filesRead: []` -> `filesRead: ["manual_override.js"]`. Agent unblocks immediately.

## 4. 🛠️ Critical Fixes & Hardening

### A. The "Penalty Box" (Anti-Zombie)
**Problem:** `Shishya` crashes, Kernel resurrects immediately, `Shishya` crashes again. Infinite loop.
**Fix:**
1.  Track `crashCount` and `lastCrashTime` in `agents` table.
2.  **Rule:** If `crashCount > 3` in `5 minutes`:
    *   Set status to `CRITICAL_ERROR`.
    *   **Do NOT** auto-resurrect.
    *   Send alert to Dashboard: "Agent Shishya is grounded. Check logs."

### B. Git "Blind Spot" Resolution
**Problem:** Agents assume `master` is static. They act on stale data.
**Fix:**
1.  **Pre-Flight Check:** Before `Sutradhar` assigns a coding task, it MUST trigger a `git fetch` (via host proxy or authorized agent).
2.  **Conflict Awareness:** If a file has changed on remote since the agent read it, the `write_file` tool should fail with `409 Conflict` and force the agent to re-read.
